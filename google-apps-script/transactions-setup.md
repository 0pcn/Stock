# 從藏股新增交易

2026-11-07：原「股票」專案已新增「藏股交易.gs」（合併下列兩個檔案），既有 API 執行檔已更新到第 2 版，部署 ID 沿用 `pages/google-config.json`。未向真實試算表寫入測試交易。

在原股票 Apps Script 專案加入兩個檔案：`transaction-rules.gs` 和 `stockfolio-transactions.gs`。保留原股票工具、`stockfolioRefreshCurrentPrices`、`writeSummaryContents_` 等函式，沿用同一個標準 Google Cloud 專案與 API 執行檔，部署新的版本。`transaction-rules.gs` 由 `node scripts/build-transaction-rules.mjs` 產生，與網頁共用驗證規則。

新增入口固定為 `stockfolioAddTransaction(requestId, transaction)`，不接受試算表 ID、分頁、函式名稱等外部指定。沿用現有三個 Google OAuth scopes，不新增授權範圍；API 執行檔必須允許目標 Google 帳號執行，帳號也必須能編輯交易、庫存、已實現損益及股利分頁。

交易寫在原「交易記錄」的 A:K。第一次成功儲存會在空白 L 欄建立「藏股交易ID」，以同一次 `setValues` 寫入交易與 ID，讓結果不明的請求可以用相同 ID 確認，不會再次新增。L 欄如已有其他內容會拒絕寫入；請勿刪除交易 ID。原始腳本在 J2:J5000 預填公式，因此新增時找實際股票代號所在的列，不用 `appendRow`，也不會把新交易寫到第 5001 列。目前上限第 4997 列，與 App 讀取範圍一致。

股數是正整數，單位為股；金額使用原試算表幣別。股票名稱、備註當作純文字處理。手續費、交易稅留空時沿用原腳本規則，明確填入時使用填寫值；不會呼叫會覆蓋其他紀錄手續費的 `recalcAllFees`。請以實際對帳單費用為準。

較早日期的交易插入較晚日期之前，同日保留原有順序並新增在同日最後；不重排其他交易。如原表日期未按順序排列，補登較早交易會先被拒絕。新增前檢查該股票完整時間序列，賣出超過持有股數會拒絕。與既有數字型 ETF 代號相容，避免把 50 與 0050 當兩個部位。

儲存後沿用原 FIFO、行情、股利與損益重建函式，整段共用 ScriptLock。寫入成功但重算失敗時，明確回傳「已儲存，庫存尚待更新」；同一視窗可用相同 ID 重新整理庫存。連線逾時時不會自動重送，保留表單與 ID，使用者可按「確認這筆紀錄」。關閉視窗或重開 App 後不保留這筆確認狀態，遇到結果不明時應先核對原交易記錄，勿另開一筆重複新增。

自動化測試使用模擬試算表驗證寫入、權限、費用、補登順序、超賣與去重，不會向真實股票表加入測試交易。
